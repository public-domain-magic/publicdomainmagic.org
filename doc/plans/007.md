# Plan 007: The Discovery workflow (the librarian's front door)

## Context

Plans 001–005 built the five bounded contexts' model layers; plan 006 shipped the
public marketing site and the read-only library. The app can now be *read* but
barely *written* — content arrives only through the console or the `db/seeds`
loader. Plan 007 begins the librarian's write surfaces.

**Architecture decision — purpose-driven workflows, not a generic admin.** We
considered `administrate` (a well-built ActiveAdmin successor) to let the librarian
edit tables directly. We rejected it: it is the anemic-CRUD shape this codebase
exists to avoid. AGENTS.md says reach into Rails before a gem; the 37signals stance
is no admin framework (the reference apps hand-roll back-office as ordinary
resources); the models skill says a controller calls **one intention-revealing
model method**, never assembles a domain operation from attribute writes; and the
whole DDD investment — bounded contexts, ubiquitous language, invariants — pays off
precisely at the layer a human touches. "Go loose on the database" discards that.
So the librarian's surfaces are **domain operations**, not table editors.

**The first operation — Discovery.** A signed-in librarian records a book they have
found, with whatever is known, to answer two questions: *could this be public
domain?* (for themselves) and *does this exist?* (for everyone). It is the honest
front of the pipeline and the living form of plan 004's "failure isn't a thing —
it's just how far it goes": a book enters knowing almost nothing and is enriched
later.

**Correctness is the requirement.** The full FRBR graph is materialized every time.
"One step" is a property of the *form the librarian fills in* — a single guided
flow — never a licence to persist a degenerate model. Where FRBR needs a curated
judgment (which expression a scan carries — the skill is explicit that expression
boundaries cannot be automated), the form asks the librarian; it never guesses.

## Post-review amendments (2026-07-24)

Folded in after a FRBR/skills + codebase review. The deltas from the first draft:

1. **Copyright status is computed, not blanket-`researching`.** Rule 1 (term expired)
   is deterministic: a known pre-1978 year *is* the answer. `TermExpiration#apply!`
   already sets `status: :determined` — you cannot both run it and stay `researching`.
   So discovery computes when it can and only opens `researching` when it genuinely
   must (see the Copyright bullet).
2. **A faithful transcription is the *same* expression.** The discriminator is a
   content change, not scan-vs-transcription; re-keying a text is a new manifestation
   of the same expression. Reframed the ontology point and the test.
3. **Never merge `Agent`s on name-string equality** (the skill's loudest invariant;
   magic is its worst case). Intake always creates fresh agents; the printed byline is
   preserved as the manifestation's `statement_of_responsibility`.
4. **Intake always creates a new `Work`** — no write-time clustering into an existing
   work (the work-set algorithm is candidate-only and overclusters; a false match trips
   three uniqueness constraints and rolls the transaction back). Dedup/merge is a later
   curated step; discovery is deliberately not idempotent.
5. Mechanical: CHANGELOG entry; `change_column_null` + view nil-guard for
   `form_of_work`; house FK rule on `ExternalReference`; RBS for the form object;
   the two-PR delivery split (ontology correction, then Discovery).

## What a discovery is, across the contexts

A discovery writes into each context through that context's own public API,
referenced by ID — never by one context reaching into another's tables.

- **Catalog** — the Work *exists* (title; approximate date; form of work if known).
  Author(s) as `Agent` + a `created` `Contribution` on the Work (creator is a
  relationship, pseudonyms and unknowns included). **Intake never merges an `Agent`
  on name-string equality** — the skill's loudest invariant, and magic is its worst
  case (one person, many names; one name, several people; names with no known person).
  Each entered author name creates a *fresh* `Agent`; authority-control/merge is a
  later curated step. The byline *as printed* is preserved separately as the
  manifestation's `statement_of_responsibility` (transcribed as-is — it coexists with
  the person link). Each **copy found online** is a real edition: a `Manifestation`
  (carrier *online resource*, bearing its **access address** — the URL) always, plus
  an `Expression` the librarian either **attaches to an existing one (content
  unchanged — a faithful scan or re-keyed transcription) or creates anew (content
  altered — modernized spelling, abridgement, etc.)**, and the `Embodiment` linking
  them; when the source print edition is itself cataloged, a `reproduction`
  manifestation-relationship records the lineage.
- **Copyright** — a `Determination` anchored to the Work (unscoped: `manifestation_id`
  nil). When a pre-1978 first-publication year is known, `TermExpiration#apply!`
  computes the public-domain date and flips the record to **`determined`**
  (`basis: term_expired`) — that deterministic countdown *is* the "could it be PD?"
  answer (future dates included). When the year is unknown or outside
  `TermExpiration.applicable?` (≥1978), the record opens in **`researching`** (or
  `unknown`) with no countdown yet — honest, and the Rule 6 track picks it up later.
- **Magic** — a public `Listing`, so the book surfaces in the library immediately
  with an honest "under research / enters the public domain on …" status. The read
  side shipped in 006.
- **Workflow** — minimal: `Project.start(work:, lead: Current.user)` (a signed-in
  librarian supplies the `lead` the seeder could not), and the `discovery` step is
  marked done.

## The ontology correction (this plan fixes a plan-004 mis-scoping)

Three things were being conflated; they are different and belong in different
contexts:

1. A **scan/transcript of the book** (Project Gutenberg, HathiTrust, archive.org) *is
   the work itself, digitized* — a Catalog **edition**, carrying its access address.
   It is always a new **manifestation**; whether it is a new **expression** turns on a
   *content change*, not on scan-vs-transcription. A faithful scan (image reproduction)
   and a faithful re-keyed transcription are the *same* expression (the words are
   unchanged) in a new manifestation — the .html/.epub/.txt/.pdf of one transcription
   are all manifestations of one expression. Only altered content (modernized spelling,
   abridgement, added apparatus) forks a new expression. Per the skill this call cannot
   be automated, so the form asks the librarian in those terms.
2. A **record about the work** (Conjuring Archive, MagicRef/Magicpedia) is a
   third-party description — evidence and an existence attestation, **not** the book.
   It becomes a first-class **external reference on the Catalog Work**, promotable to
   a Copyright `Citation` when an investigation later cites it.
3. **Workflow owns only our own production** — the scan set *we* upload, *our* text
   repository, *our* published ePub. It does not track where the book otherwise
   exists or what other archives say. Plan 004 wrongly gave `Workflow::Resource`
   external kinds (`hathitrust_scans`, `google_books_scans`, `pg_transcript`,
   `pg_ebook`, `archive_scans`); this plan removes them. Correct is the only option.

## Model changes (migration + model + RBS + fixtures + tests, no shortcuts)

### Catalog
- **`catalog_manifestations.access_address`** (string, nullable) — the FRBR
  manifestation "access address" for a remote resource. Print editions have none;
  digital editions carry their URL. Surface it in the library as "where to read it."
- **An "online resource" carrier** — a `Catalog::Carrier` value for digital
  editions (seed + fixture).
- **`catalog_works.form_of_work_id` becomes nullable** — at discovery the form may
  be unknown; `nil` is honest, better than a fabricated "Unknown" sentinel row.
  Migration is `change_column_null :catalog_works, :form_of_work_id, true` (the column
  is `null: false` today); `Catalog::Work` drops the required `belongs_to
  :form_of_work` → `optional: true`; and `books/show` gets a nil-guard where it prints
  the form.
- **`Catalog::ExternalReference`** (new): `belongs_to :work` (FK `foreign_key: {
  to_table: :catalog_works }`, per the plan-001 house rule),
  `url` (presence), `source` (e.g. "Conjuring Archive"), `note` (text). Unique
  `[work_id, url]`. A record *about* the work — attests existence, anchors work
  identity (the variant-authority signal the work-set algorithm leans on), and is
  the raw material a Copyright `Citation` later formalizes.
- The `reproduction` manifestation-relationship already exists (plan 001); the
  discovery flow uses it only when both ends are identified records (per the
  relationships skill — never a guess).

### Workflow (the correction)
- `Workflow::Resource::KINDS` becomes our-artifacts-only:
  `%w[ ia_scan_set text_repo pdm_ebook other ]`. The external kinds move to Catalog
  (editions) / Catalog external references. Reconcile fixtures, the seeder, and the
  plan-004 tests. `text_repo` uniqueness and URL presence are unchanged.

### Copyright / Magic
- No structural change. Discovery *uses* `Copyright::Determination` (open in
  `researching`) and `Magic::Listing` (public) via their existing APIs.

### The 006 book page follows the corrected model
- Today `books/show.html.erb` builds "where to read it" from `@project.resources`
  filtered to `%w[ pdm_ebook pg_ebook pg_transcript hathitrust_scans archive_scans
  google_books_scans ]` — four of those kinds are removed by this plan. It now reads
  **Catalog online editions** (manifestations with an `access_address`) plus our
  `Workflow` `pdm_ebook` when published. `pdm_ebook` survives the KINDS pruning, so the
  existing `books_controller_test` "downloadable resource" case still holds; add a new
  fixture + request test covering the Catalog-manifestation reader path.

## The Discovery operation

An `ActiveModel::Model` **form object** — `Discovery` (top-level: it is an
application-level use case owned by no single context) — is the one
intention-revealing entry point. Fields: title, date, author names, first
publication year/country, optional form of work, exposure (default `public`); nested
**found copies** (url, source, byline-as-printed, the librarian's *same-content /
altered-content* expression call, optional "reproduction of" a known edition); nested
**external references** (url, source, note); notes.

`#save` runs one transaction that:
1. **always creates** a new Catalog `Work` (never clusters into an existing one at
   write time — see below) + a *fresh* `Agent` per author name (never merged on name
   equality) with `created` `Contribution`s, then each found copy's `Manifestation`
   (online carrier + access address + `statement_of_responsibility`) attached to an
   existing or new `Expression` per the librarian's content call, plus its
   `Embodiment` and any `reproduction` link, and each `ExternalReference`;
2. builds the `Copyright::Determination` for the Work: if a pre-1978 year is known,
   `TermExpiration#apply!` → `determined` + countdown; otherwise `researching`/`unknown`;
3. `Workflow::Project.start(work:, lead: Current.user)` — which already seeds the
   step ledger — then `project.steps.complete(:discovery, by: Current.user)`;
4. creates the public `Magic::Listing` (exposure defaulting to `public`).

It coordinates by calling each context's public API (the FRBR-chain construction
stays inside Catalog's own models), never by reaching into another context's
internals. It is a form object, not a service layer.

**Not idempotent, by design.** Discovery has no natural-key guard: recording the same
book twice yields a second Work/Project/Listing/Determination. That is acceptable —
intake is human-driven and deduplication is a later curated workflow (the work-set
algorithm produces *candidates* for review, not authoritative merges). The `new` form
may surface look-alike works as a soft "these look similar — still record it?" hint,
but it never blocks or auto-attaches.

## Routes, controller, view

- `resources :discoveries, only: %i[ new create ]`, guarded by `LibrarianAccess`
  (`can_catalog?`). A discovery is a resource named for the noun — no custom verbs.
- `DiscoveriesController#new` builds a `Discovery`; `#create` calls `discovery.save`
  and, on success, redirects to the new book's public page (`books#show`) so the
  librarian immediately sees "it exists"; on failure re-renders `new` with errors.
- `discoveries/new.html.erb` — a semantic form (Simple.css, per the marketing
  design and modern-web-guidance): `fields_for`-style nested rows for found copies
  and external references, native inputs and validation, web-platform first, Stimulus
  only if a repeatable-row control genuinely needs it.

## Tests

- **`Discovery` form object:** a full discovery builds the entire graph — Work,
  authors as fresh agents + `created` contributions, each found copy's expression +
  online manifestation (with access address + statement of responsibility) +
  embodiment, external references, a `determined` determination with a live countdown
  (pre-1978 year), a started project with `discovery` done, and a public listing; an
  invalid discovery rolls the whole transaction back.
- **Determination status is computed:** a pre-1978 year yields `determined` +
  countdown; an unknown/≥1978 year yields `researching` (or `unknown`) and no
  countdown — the same input the "could it be PD?" answer reads.
- **Content-driven expression call:** unchanged content (faithful scan *or* faithful
  transcription) attaches to the existing expression; altered content creates a new
  one — driven by the form input, not by the medium, not guessed.
- **Agents are never merged:** discovering two different books whose bylines share a
  name string creates two agents (the name↔person invariant), not one.
- **Requests:** a librarian GETs `new` and POSTs `create` → redirect to the book
  page; a role-less visitor is forbidden (`can_catalog?`); the discovered book then
  appears in the public library with its status/countdown.
- **Catalog:** manifestation `access_address`; `ExternalReference` validations +
  `[work_id, url]` uniqueness; `Work` valid with no form of work.
- **Workflow correction:** removed kinds are invalid; the surviving our-artifact
  kinds valid; fixtures/seeder reconciled.
- **006 regression:** the book page's "where to read it" reads Catalog editions.

## Scope discipline (what this is NOT)

- Not full cataloging — discovery is *intake*; deepening the FRBR record (adding
  more expressions/editions, relationships, items, aggregates) is a later
  "catalog a work" workflow.
- Not the Copyright researcher workbench (investigations/clearances UI) — the
  separate deferred track.
- Not a Workflow pipeline UI (advancing steps, uploading our scan set) — later.
- Not the trick-level model (`doc/contributors/magic-taxonomy-research.md`).

  rejected).
