# Plan 001: Complete the Catalog Bounded Context (FRBR/WEMI Model Layer)

## Context

The Catalog bounded context implements FRBR/WEMI (see `.agents/skills/frbr-wemi/`). The
current schema (12 migrations, June 2026) has the right spine — Work → Expression →
Manifestation → Item with correct chain direction — but models only the 1:1:1 fast path.
Assessed gaps:

1. **Expression↔Manifestation is 1:N, not M:N** — no aggregates (anthologies, augmented
   editions, compilations) can exist. FRBR requires many-to-many; ~20% of real holdings
   are aggregates.
2. **Inheritance-fallacy columns** — `catalog_manifestations.language_id` and
   `.form_of_expression_id` are expression-level attributes forced (null: false) onto
   every manifestation.
3. **No Group 2** — no agents, no name variants, no role-typed contributions. "Creator is
   a relationship, not an attribute."
4. **No same-level relationships or whole/part** — no adaptation/successor links, no
   reproduction links for facsimiles, no serials/components.
5. **No Group 3** — no concepts, no has-as-subject.
6. Smaller: `series_id` mandatory; no manifestation identifier/place; `t.date` forces
   false precision on "1584"; `languages.code` limit 2 excludes ISO 639-2/3 codes;
   HABTM join table escaped the `catalog_` prefix; `Catalog::Medium` declares
   `has_many :works` (should be `:manifestations`).

**Scope: Catalog only.** Copyright, Magic, and Workflow are separate bounded contexts
(DDD); see "Context seams" at the end. Model layer only — controllers/views get the
minimal edits required to keep the app green.

### Pre-existing defects this plan must absorb

- **Broken foreign keys (latent, affects every table).** The existing migrations used
  `foreign_key: true`, which derives the target table from the column name and ignores
  `table_name_prefix` — so every FK targets a nonexistent unprefixed table
  (`add_foreign_key "catalog_expressions", "works"` in schema.rb; `REFERENCES
  "expressions"` in sqlite_master). With SQLite FK enforcement on, runtime inserts fail;
  fixtures only load because fixture insertion disables referential integrity.
  **House rule from here on: always `foreign_key: { to_table: :catalog_* }`.**
- **Red test suite.** `test/fixtures/catalog/languages.yml` has two rows with
  `code: MyString` against a unique index — fixture loading already fails. There is no
  green baseline to preserve; the first fully green run is after all steps land.
- Both dev and test DBs are empty — no data migrations needed anywhere.

### Decisions already made

- Group 2 = single `Catalog::Agent` table with string-enum `kind` (person |
  corporate_body) + `Catalog::Nomen` name variants. Bibliographic data only —
  researched biographical facts (residency, heirs, sources) belong to the Copyright
  context.
- Dates on works/expressions become EDTF-style strings ("1584", "1924/1928").
  `manifestations.date_of_publication` stays a real date.
- String-backed enums (`%w[...].index_by(&:itself)`) with `validate: true`, per house
  style and so vocabulary tests get validation errors instead of `ArgumentError`.
- Fixtures use real bibliography: *The Royal Road to Card Magic* (from the Rule 6
  dossier data) and *The Discoverie of Witchcraft*.
- New Ruby files carry the house header (`# frozen_string_literal: true` + SPDX block,
  as in `app/models/application_record.rb`); files we touch get brought up to standard.

## Step 2 — Migration hand-edits

Every generated `foreign_key: true` must be edited to `foreign_key: { to_table:
:catalog_* }` — the shorthand is what produced the broken FKs.

**Create-table migrations** (add `null: false` where shown; explicit index names because
auto-generated composite names exceed 62 chars and get hashed):

- `create_catalog_agents`: `name` and `kind` null: false.
- `create_catalog_nomens`: agent ref → `to_table: :catalog_agents`; `name`, `kind`
  null: false.
- `create_catalog_contributions`: agent ref → `to_table: :catalog_agents`;
  `t.references :contributable, polymorphic: true, null: false` (no FK — polymorphic
  columns cannot have DB foreign keys); `role` null: false.
- `create_catalog_embodiments`: refs → `catalog_manifestations` / `catalog_expressions`;
  `t.index %i[ manifestation_id expression_id ], unique: true, name:
  "index_catalog_embodiments_uniqueness"`.
- `create_catalog_work_relationships`: both refs → `to_table: :catalog_works`; `kind`
  null: false; `t.index %i[ work_id related_work_id kind ], unique: true, name:
  "index_catalog_work_relationships_uniqueness"`. Same pattern for
  `expression_relationships` (→ `catalog_expressions`) and
  `manifestation_relationships` (→ `catalog_manifestations`).
- `create_catalog_concepts`: `name` null: false, unique index.
- `create_catalog_subjects`: work ref → `to_table: :catalog_works`; polymorphic
  `subject` null: false, no FK; `t.index %i[ work_id subject_type subject_id ],
  unique: true, name: "index_catalog_subjects_uniqueness"`.

**`OverhaulCatalogManifestations`:**

```ruby
def change
  remove_reference :catalog_manifestations, :expression, null: false, foreign_key: { to_table: :expressions }
  remove_reference :catalog_manifestations, :language, null: false, foreign_key: { to_table: :languages }
  remove_reference :catalog_manifestations, :form_of_expression, null: false, foreign_key: { to_table: :form_of_expressions }
  change_column_null :catalog_manifestations, :series_id, true
  add_column :catalog_manifestations, :identifier, :string
  add_column :catalog_manifestations, :place_of_publication, :string
end
```

The `foreign_key:` options describe the FKs *as they wrongly exist* (unprefixed), so
removal and rollback both work. If `remove_reference` balks, fall back to
`remove_foreign_key :catalog_manifestations, column: :expression_id` (identify by
column, never by to_table) + `remove_column`.

**`FixCatalogForeignKeys`** — repairs the 8 surviving broken FKs (the 3 on
manifestations die in the previous migration). Must run *before* the type-change
migrations so SQLite's table rebuilds copy corrected FKs:

```ruby
REPAIRS = {
  catalog_expressions: { form_of_expression_id: :catalog_form_of_expressions,
                         language_id: :catalog_languages,
                         work_id: :catalog_works },
  catalog_items: { condition_id: :catalog_conditions,
                   manifestation_id: :catalog_manifestations },
  catalog_manifestations: { medium_id: :catalog_media,
                            series_id: :catalog_series },
  catalog_works: { form_of_work_id: :catalog_form_of_works }
}.freeze

def up
  REPAIRS.each do |table, columns|
    columns.each do |column, to_table|
      remove_foreign_key table, column: column
      add_foreign_key table, to_table, column: column
    end
  end
end

def down
  # The old foreign keys pointed at nonexistent tables; do not restore them.
end
```

**`ChangeCatalogDatesToStrings`** — explicit `up`/`down` (`change_column` is
irreversible in `change`): works.date and expressions.date `:date` → `:string`.

**`ExpandCatalogLanguageCode`** — `change_column :catalog_languages, :code, :string,
limit: 3` (up) / `limit: 2` (down). The rebuild preserves the unique index.

**`RenameIntendedAudiencesWorksJoinTable`** — `rename_table :intended_audiences_works,
:catalog_intended_audiences_works`.

**`RenameCatalogMediaToCatalogCarriers`** — `rename_table :catalog_media,
:catalog_carriers` and `rename_column :catalog_manifestations, :medium_id, :carrier_id`.
Generated last, it runs after `FixCatalogForeignKeys` (whose REPAIRS hash still
correctly says `medium_id: :catalog_media` at that point); SQLite's ALTER TABLE RENAME
propagates the rename into the repaired FK. **Ubiquitous-language fix**: FRBR's manifestation
attribute for values like "print"/"PDF" is *form of carrier*; "physical medium" means
paper/vellum. The model becomes `Catalog::Carrier` (`has_many :manifestations`),
`Manifestation belongs_to :carrier`; fixtures move to `carriers.yml`; collateral:
rename the media controller/views/routes entry (`resources :media` → `:carriers`) and
the `medium_id` references in manifestation params/views/tests.

## Step 3 — Model files

All new/rewritten files get the frozen-string + SPDX header. `dependent:` options are
required wherever a destroy would now hit an enforced FK. Within the `Catalog`
namespace, association targets resolve without `class_name:` except on `related_*`

**New models** (full sketches):

```ruby
# FRBR Group 2 / LRM: a person or corporate body responsible for the
# creation, realization, production, or ownership of resources.
class Catalog::Agent < ApplicationRecord
  KINDS = %w[ person corporate_body ].freeze

  has_many :nomens, dependent: :destroy
  has_many :contributions, dependent: :destroy

  enum :kind, KINDS.index_by(&:itself), validate: true

  validates :name, presence: true
end
```

```ruby
# IFLA LRM: an appellation by which an agent is known — birth names, legal
# names, spellings, stage names, pen names. A person and a name are different
# things; never merge agents on name-string equality.
class Catalog::Nomen < ApplicationRecord
  KINDS = %w[ birth legal spelling stage pen ].freeze

  belongs_to :agent

  enum :kind, KINDS.index_by(&:itself), validate: true

  validates :name, presence: true
end
```

```ruby
# FRBR: creator/contributor is a relationship, not an attribute. Links an
# agent to the WEMI level its role operates on.
class Catalog::Contribution < ApplicationRecord
  ROLES_BY_LEVEL = {
    "Catalog::Work"          => %w[ created ],
    "Catalog::Expression"    => %w[ wrote translated edited illustrated performed taught ],
    "Catalog::Manifestation" => %w[ published printed ],
    "Catalog::Item"          => %w[ owned donated annotated ]
  }.freeze

  belongs_to :agent
  belongs_to :contributable, polymorphic: true

  enum :role, ROLES_BY_LEVEL.values.flatten.index_by(&:itself), validate: true

  validate :role_appropriate_for_level

  private
    def role_appropriate_for_level
      return if role.blank? || contributable_type.blank?
      return if role.in?(ROLES_BY_LEVEL.fetch(contributable_type, []))

      errors.add(:role, "#{role} is not a #{contributable_type.demodulize.downcase}-level role")
    end
end
```

(The enum derives from `ROLES_BY_LEVEL` so the two can't drift.)

```ruby
# FRBR: "is embodied in" — the many-to-many link between expressions and
# manifestations. This is where aggregates live.
class Catalog::Embodiment < ApplicationRecord
  belongs_to :manifestation
  belongs_to :expression

  validates :expression_id, uniqueness: { scope: :manifestation_id }
end
```

## Gotchas (verified)

1. `foreign_key: true` + `table_name_prefix` derives to_table from the column name —
   always spell out `to_table:` in this app.
2. Without `enum ..., validate: true`, out-of-vocabulary assignment raises
   `ArgumentError` instead of failing validation — always pass `validate: true`.
3. SQLite DDL = table rebuilds; run the FK repair before type changes; `change_column`
   needs explicit up/down.
4. Identify broken FKs by `column:`, never by to_table.
5. Polymorphic columns get no DB FK (model validation only); polymorphic fixtures use
   `label (Catalog::ClassName)` syntax.
6. Composite index names > 62 chars get hashed — pass explicit `name:`.

## Context seams (documented, not built)

The other bounded contexts will reference Catalog **by ID only**, each keeping its own
model of overlapping ideas:

- **Copyright** (PG rules; auditor UI for legal): e.g. a future
  `Copyright::Clearance belongs_to :work, class_name: "Catalog::Work"`. Researched
  biographical facts (citizenship, residency, heirs, per-assertion sources — the Rule 6
  dossier data) live here, NOT on `Catalog::Agent`. Catalog serves Rule 6's
  bibliographical phase for free: alternate titles = manifestation titles;
  republications = manifestations + reproduction relationships; serialization =
  whole/part.
- **Magic** (public search): Effect/Trick/Method/Patter models mapping to Catalog per
  the context map at `.agents/skills/frbr-wemi/references/magic.md` (effect →
  `Catalog::Concept`, routine → `Catalog::Work`, etc.).
- **Workflow** (discover → research → PG approval → scan/OCR → Standard Ebooks
  edition): pipeline state references `Catalog::Work`/`Manifestation`; produces new
  `Catalog::Manifestation` rows (the PDM ebook editions) as output.
