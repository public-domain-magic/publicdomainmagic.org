# Plan 004: Workflow Bounded Context (Model Layer)

## Context

Workflow tracks a book's journey: learn it exists → gather frontmatter facts → survey
existing sources (PG/HathiTrust/etc.) → copyright path (Rule 1 wait or Rule 6 research,
delegated to the Copyright context) → find or make scans → find or make a transcription
→ the Gutenberg→Standard-Ebooks text pipeline → publish on PublicDomainMagic.org →
optional print editions (collectible hardcover; budget softcover for beginner-friendly
titles only).

Domain constraints from the owner:

- **"Failure isn't a thing — it's just how far it goes."** Progressive enrichment, not a
  linear state machine with dead ends. A brand-new book can enter the system and simply
  wait 95 years (the countdown lives in Copyright, plan 003).
- **Actors baked in from the beginning** (plan 002 Users; Researcher/Librarian roles),
  though Kerrick is the only actor for now.
- **Big artifacts never live in this app**: scan sets are ~80 GB (they go to Internet
  Archive); each book's text becomes a git repository (branches/templating for
  PG-vs-SE spelling rules is that repo's concern, not this app's). The app stores
  *references* (URLs).
- **The whole PG→SE text pipeline is ONE step**: to-do / in progress / done. Done ⇒
  downloadable.
- A work becomes publicly visible (Magic context) as soon as it has enough data — even
  if all we can do is link out to HathiTrust scans or a PG transcript.

Design consequence: a **step ledger**, not a status column. A `Workflow::Project` (one
per catalog work) has `Workflow::Step` rows of fixed kinds, each independently
todo/in_progress/done/skipped with an actor and notes. "How far it goes" = which steps
are done; nothing blocks anything except real dependencies enforced as advisory
predicates, not DB constraints (the owner explicitly iterates out of order).

## Entities

Namespace module `Workflow`, `table_name_prefix "workflow_"`. FKs always
`foreign_key: { to_table: ... }`.

### `Workflow::Project` (one per catalog work)

| column | notes |
|---|---|
| work (FK → catalog_works, unique) | |
| lead (FK → users) | default `-> { Current.user }` once Current is wired |
| edition_manifestation (FK → catalog_manifestations, nullable) | the PDM ebook edition this pipeline produces, once it exists |
| notes | text |

Associations: `has_many :steps`, `has_many :resources`. Convenience predicates read the
ledger: `downloadable?` = step(:text_pipeline).done?; `published?` =
step(:publication).done?.

On create, seed the ledger: `after_create` builds one Step per KIND in `todo` (single
place: `Project#seed_steps`, called from a creation method — house style prefers an
intention-revealing `Project.start(work:, lead:)` over callbacks; use the class method).

### `Workflow::Step` (the ledger)

| column | notes |
|---|---|
| project (FK) | |
| kind | string enum, one row per kind per project (unique [project_id, kind]) |
| status | enum `%w[ todo in_progress done skipped ]` |
| actor (FK → users, nullable) | who did/is doing it |
| happened_on | date, nullable — when it reached done |
| note | text |

```ruby
KINDS = %w[
  discovery
  bibliographic_research
  source_survey
  copyright_clearance
  scans
  transcription
  text_pipeline
  publication
  print_collectible
  print_budget
].freeze
```

Mapping to the owner's states: 1→discovery, 2→bibliographic_research, 3→source_survey,
R1–R4→copyright_clearance (detail lives in Copyright::Dossier/Clearance; this step's
status mirrors the outcome: done when `Determination#public_domain?` or
`Clearance#cleared?`), P1+P3→scans, P2→transcription, P4+P5+P6→text_pipeline (the ONE
step), P7→publication, P8→print_collectible, P9→print_budget. The optional print steps
default to `skipped` for non-applicable books (budget softcover only for
beginner-friendly titles — that classification is Magic's, plan 005).

Write API on the association, house style:

```ruby
has_many :steps do
  def [](kind) = find_by!(kind:)
  def complete(kind, by: Current.user, note: nil)
    self[kind].update!(status: :done, actor: by, happened_on: Date.current, note:)
  end
end
```

### `Workflow::Resource` (external references)

| column | notes |
|---|---|
| project (FK) | |
| kind | string enum `%w[ hathitrust_scans archive_scans google_books_scans pg_transcript pg_ebook ia_scan_set text_repo pdm_ebook other ]` |
| url | string, presence |
| note | string |

`text_repo` is the git repository locator for the book's text — an opaque string with
presence validation only, no format validation (it may be an SSH clone URL like
`git@host:books/royal-road.git`, not necessarily https). `ia_scan_set` is the uploaded
scan set; `pg_ebook` the published Gutenberg ebook; `pdm_ebook` the final downloadable.
Multiple rows per kind allowed except `text_repo` (unique per project).

## Generators

```sh
bin/rails g model workflow/project work:references lead:references \
  edition_manifestation:references notes:text
bin/rails g model workflow/step project:references kind:string status:string \
  actor:references happened_on:date note:text
bin/rails g model workflow/resource project:references kind:string url:string note:string
```

Hand-edits: `work` → `to_table: :catalog_works` + unique index; `lead`/`actor` →
`to_table: :users`; `edition_manifestation` → `to_table: :catalog_manifestations`,
nullable; step unique index `[project_id, kind]`; resource partial unique index on
`[project_id, kind]` where kind = 'text_repo' (SQLite supports partial indexes:
`add_index ..., unique: true, where: "kind = 'text_repo'"`).

## Model behavior worth testing

- `Project.start(work:, lead:)` creates the project + all ten steps in `todo`.
- `steps.complete(:text_pipeline, by: user)` marks done with actor + date;
  `project.downloadable?` flips true.
- Steps enforce kind/status vocabularies (enum `validate: true`); one step per kind.
- Advisory dependency predicates (no hard gates): e.g.
  `Project#ready_to_publish?` = text_pipeline done AND (copyright_clearance done OR
  determination public_domain). Belongs on Project, reading the Copyright seam.
- `Resource` URL presence; text_repo uniqueness per project.

- `resources.yml`: royal_road text_repo (git URL placeholder), greater_magic other
  (a dealer listing URL, note "copy acquired, awaiting scan").

## Tests

Per the behavior list above, plus: completing a step twice is idempotent-safe
(`update!` on done row); `downloadable?` false until text_pipeline done; unique
project-per-work; step ledger seeded exactly once (calling `start` twice for a work
fails on the unique work index).

## Context seams

- **Catalog**: project ↔ work (unique); the pipeline's output edition is a new
  `Catalog::Manifestation` (created by a Librarian; Workflow stores the reference).
- **Copyright**: the `copyright_clearance` step's status mirrors
  `Copyright::Determination#public_domain?` / `Clearance#cleared?`; a small sync method
  on Project (called when Copyright records change, or checked lazily) — keep it a
  read, not a callback across contexts.
- **Magic** (plan 005): public visibility is driven by Catalog data existing, not by
  Workflow state; `downloadable?` + plan 002's `can_download_advanced?` + Magic's
  beginner/advanced classification together gate the download button. External
  `Resource` links (HathiTrust, PG) are what the public UI offers before a PDM edition
  exists.
- **Users** (plan 002): `lead`/`actor`; guard mutations with `can_research?` /
  `can_catalog?` at the controller layer later.
