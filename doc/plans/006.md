# Plan 006: Public Library UI (Magic read surface) + real-data seeding

## Context

The model layer is complete for all five bounded contexts (plans 001–005) and the
full gate is green, but the app has **no public face**: the root is still the
`pages#home` placeholder (plan 002), and the only UI is Catalog's generated
back-office scaffolds. This plan builds the first public-facing surface — the
**read-only public library**, Magic's reading experience — and reclaims the root
route the memory note reserved for it.

Two owner decisions shape the plan and override any default:

- **Read-only. No write UI.** Content enters through a **YAML-driven seeder** —
  fixture-shaped `.yml`, but loaded *through the model layer* (validations,
  normalization, enums all run) into the dev **and production** databases. A
  Librarian curates the corpus in YAML + console for now; the write/admin UI is a
  later plan.
- **Front end.** *Revised after review.* The library/catalog markup is semantic,
  accessible, web-platform-first HTML (`<form>`, `<details>`, `<time>`,
  `<meter>`-worthy status — native validation; Stimulus only where the platform
  can't). The **marketing home + static pages restore the prior iteration's
  design** (Simple.css + the OFL serif webfonts Crimson Pro / League Spartan /
  Sorts Mill Goudy + the inline `pdm_logotype`), and the whole site inherits that
  layout. So this is no longer "no CSS": the base design is in; only *further*
  visual polish is deferred. (The earlier no-CSS/Zen-Garden framing is superseded
  for these surfaces.)

### Skills

- **`modern-web-guidance`** — the authority for the HTML/accessibility/web-platform
  approach; installed at `~/.agents/skills/modern-web-guidance/`. It is a **search
  tool, not a static doc**: at the start of each view/component, run
  `npx -y modern-web-guidance@latest search "<action query>" --skill-version 2026_05_16-c5e78707`
  then `retrieve "<id>"` for the matching guide, and follow it (its top-level
  `guides/html`, `guides/accessibility`, and `guides/forms` govern this plan's
  markup). Treat "Baseline Widely available" features as safe; follow each guide's
  fallback note otherwise. The `guides/css*`, `guides/motion`, `guides/scroll`, and
  `guides/typography` families belong to the **later styling plan**, not this one.
- **`rails-37signals-controllers-routing`**, **`rails-37signals-frontend`** — Rails
  mechanics: thin RESTful controllers, resource-per-concept, `scope module:`,
  partials-take-locals, `dom_id`, one-layout-with-regions, helpers build tags.
- **`rails-37signals-testing`** — Minitest + fixtures, real `sign_in`, few/no system
  tests.

### Scope discipline (what this is NOT)

- No Magic/Catalog **write UI** (console + seeder only).
- No **CSS / design system** — deferred to a dedicated styling plan (the whole point
  of the Zen-Garden constraint).
- No **trick-level models** (`doc/contributors/magic-taxonomy-research.md`).
- No **PG submission export/automation** (plan 003 appendix).
- **Search is basic** (cross-field match), not faceted; SQLite FTS5 (per the models
  skill) is the documented upgrade for when the corpus grows — noted, not built.

## Decisions

- **Visibility ≠ downloadability.** Per plan 005, `exposure` gates *downloads*, not
  discoverability: a `protected` book still appears in browse and on its detail page;
  only its method-bearing artifacts are gated. `Listing#accessible_to?(Current.user)`
  is the one predicate deciding the "get this book" section.
- **Public/back-office split.** The library is top-level and unauthenticated
  (`allow_unauthenticated_access`, still *restoring* a session so a signed-in
  magician is recognized). The existing `catalog/*` scaffolds become the Librarian
  back-office and finally get the **`can_catalog?` guard** that plan 002 deferred
  "to the controller layer, later" — closing that seam.
- **Authorization is a predicate, not a scope, here.** The controllers-routing
  skill's structural "scope through `Current.user`" pattern does not apply to
  world-readable data; the download gate is the `accessible_to?` capability check,
  and back-office writes use a one-line `ensure_can_catalog` guard.
- **Clean URLs, no gem.** `Magic::Listing#to_param = "#{id}-#{work.title.parameterize}"`;
  look up by leading id (built-in, zero migration, stable). No FriendlyId.
- **Seeds are distinct from fixtures.** Fixtures stay test-only. Seeds are the real
  dev/prod corpus in `db/seeds/*.yml`, loaded idempotently through the models. They
  do not share files and must not be coupled.

## Step 1 — Routes (root is the marketing home, not the search)

**Revised after review:** the root is a *marketing* home page (a Standard-Ebooks-
style landing that says what PDM is and funnels into the catalog), restored from
this repo's own earlier iteration (commit `bff3c24`/`f6639f2`). The search/browse
**library lives at `/books`**, not the root.

```ruby
root "pages#index"                       # the marketing home
scope "/about", as: "about" do           # static pages
  get "/",             to: "pages#about"
  get "/our-goals",    to: "pages#about_our_goals",    as: "our_goals"
  get "/exposure",     to: "pages#about_exposure",     as: "exposure"
  get "/dual-license", to: "pages#about_dual_license", as: "dual_license"
  get "/accessibility", to: "pages#accessibility",     as: "accessibility"
end
get "/contribute", to: "pages#contribute", as: "contribute"
get "/newsletter", to: "pages#newsletter", as: "newsletter"

resources :books, only: %i[ index show ] # the library: browse/search + a book
get "/ebooks", to: "books#index", as: "ebooks"  # marketing name for the catalog
resources :tags,  only: :show
```

`books#index` reads `params[:q]` for search. Keep `resource :session`,
`first_run`, `passwords`, and the `catalog` namespace as-is.

## Step 2 — Public controllers (thin, unauthenticated)

- `BooksController` — `allow_unauthenticated_access` (+ session restore). `index`
  lists `Magic::Listing`s (featured first), optionally filtered by `params[:q]`;
  `show` loads one listing by id and renders the book. No `Current.user` scoping —
  public data. Empty-body actions where the template does the work.
- `TagsController#show` — the listings for a tag (a tag page is just a filtered
  browse). `allow_unauthenticated_access`.
- Eager-load bundles as named scopes on `Magic::Listing`
  (`with_book_details` → work, contributions/agents, embodiments/manifestations,
  subjects/concepts, tags, purchase_links) to avoid N+1 on the detail page.

## Step 3 — Back-office guard (closes plan 002's seam)

- Add `app/controllers/concerns/librarian_access.rb`: `before_action :ensure_can_catalog`
  → `head :forbidden unless Current.user&.can_catalog?`. Include it in the
  `Catalog::*` controllers (they are currently only `require_authentication`).
- Phrase as a capability (`can_catalog?`), never a role check, per the auth skill.

## Step 4 — Views (semantic HTML, zero CSS)

One layout, regions via `content_for`; a `<link>` slot left empty for later skinning.
Landmarks: `<header>` (site name, nav, sign-in/out), `<main>`, `<footer>`.

- `books/index` — a `<search>` landmark wrapping a GET `<form>` (native validation,
  no JS); a `<section>` for featured; the results as an `<ol>` of `<article>`s,
  each rendered by the shared `_book` partial (locals, `dom_id`). A book with a
  future public-domain date shows its countdown.
- `books/show` — `<article>` with `<h1>` work title; a `<dl>` of bibliographic facts;
  **creators** as a role-typed list (Catalog contributions → agents, using the
  preferred nomen); **editions** differentiated by language / year / carrier inside
  a `<details>` (the FRBR "users select by expression/manifestation" gotcha — collocate
  by work, differentiate below); **subjects/tags** as links to `/tags/:id`;
  **copyright status** as a `<p>` with `<time datetime>` for the PD date and the
  countdown when future (reads `Copyright::Determination#public_domain?` /
  `countdown_days`); the **"get this book"** section gated by
  `listing.accessible_to?(Current.user)` — when open, `Workflow::Resource` links
  grouped by kind (read/download/scans/transcript, external now, `pdm_ebook` when it
  exists); when gated, a short note + sign-in prompt; **purchase links** as an
  `<aside>`.
- Helpers build tags (state→attribute, `<time datetime>`), one module per resource;
  `ApplicationHelper` stays tiny.

## Step 5 — JavaScript (only where the platform can't)

Prefer built-ins. The one clearly-justified Stimulus controller is `local-time`
(render `<time datetime=…>` server-side in UTC/ISO; localize to the viewer's zone
client-side) — the frontend skill's canonical "time is client-side" case. A live
countdown tick may progressively enhance the server-rendered number, but the page
must be fully correct and usable with JS off. No other controllers in this plan.

## Step 6 — Search (basic, honest)

`books#index` with `params[:q]` matches across work title, creator (agent/nomen)
names, and tag/subject names via joins + normalized `LIKE` (case/diacritic-folded).
No FTS5 index yet — the corpus is small and the maintenance-in-callbacks cost isn't
warranted at launch. **Log the limitation** in the code and this plan: FTS5
(`references/patterns.md`) is the upgrade path when the library grows. A blank query
lists everything.

## Step 7 — The seeder (real bibliography, idempotent, through the models)

- **Mechanism.** `db/seeds/*.yml` (one file per entity, fixture-shaped: string
  labels, label references for associations) loaded by a `Seeds::Loader` PORO
  (`app/models/seeds/loader.rb`, house-style plain object, one public verb) invoked
  from `db/seeds.rb`. **Not** `ActiveRecord::FixtureSet` — that bypasses validations,
  normalization, and callbacks and forces IDs. The loader instantiates models, runs
  the real API, and resolves labels → records within a run.
- **Idempotency.** Each entity declares a **natural key** for `find_or_create_by!`
  (Work: normalized title + date; Agent: name + birth/death; Listing: work; Tag:
  name; Determination: work + manifestation; Resource: project + url). Re-running
  `bin/rails db:seed` is a no-op on existing rows and only inserts new YAML entries.
  Safe in production; no destructive operations.
- **Order & seams** (labels resolve across files): Catalog (agents → nomens → works →
  expressions → manifestations → embodiments → contributions → concepts → subjects)
  → Copyright (determinations, for PD/countdown badges) → Workflow (projects +
  resources, for the "get it" links) → Magic (listings → purchase_links → tags →
  taggings). Each context is written through its own model API only.
- **Content (launch corpus).** Only the **already-researched titles** ship in the
  first seed: *The Royal Road to Card Magic* (public; full Rule 6 dossier),
  *The Discoverie of Witchcraft* (public; long-past PD), and *Greater Magic*
  (protected + the countdown to 2034-01-01). These already carry verified
  bibliographic + copyright data in the repo. The seed YAML is designed to grow: each
  further title is a data-entry task (a Librarian activity), not a code change — new
  rows, no new mechanism.

## Step 8 — Tests

- **Requests (integration):** unauthenticated visitor GETs root and a book show;
  browse lists both public and protected books; the **download-gate matrix at the
  request level** — signed-out and role-less users see no download section on a
  protected book, a vetted magician and Kerrick do, and every visitor sees it on a
  public book; search returns expected titles; a blank query lists all; a tag page
  lists its books.
- **Back-office guard:** a signed-in user without `can_catalog?` gets `403` on
  `catalog/works#new`/`create`; a librarian succeeds (the plan-002 seam, now tested).
- **Seeder:** loading twice is idempotent (row counts stable, no duplicates);
  associations resolve across contexts; an invalid row raises (validations run). Use a
  small seed YAML directory as the test input.
- **System tests:** none — a no-JS read-only site is fully covered by request tests
  (testing skill: keep system tests few). Revisit if the `local-time`/countdown JS
  grows real behavior.
- Real `sign_in` helper; never stub `Current`.
