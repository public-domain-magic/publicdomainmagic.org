# Plan 005: Magic Bounded Context (Model Layer)

## Context

Magic is the public-facing domain context: the conjuring semantics (effects, tricks,
categories) powering search/browse, plus the access rules for downloads and the
commerce hooks (affiliate links, the *Greater Magic* countdown hype). All data is
hand-entered by Librarians at launch. It references Catalog by ID; the FRBR mapping is
the context map at `.agents/skills/frbr-wemi/references/magic.md` (effect-as-plot →
`Catalog::Concept`, routine → `Catalog::Work`, publications → manifestations).

Research inputs (July 2026, sub-agent reports):

- **Conjuring Archive** (3.7k publications, 188k entries, 2,882-node category tree):
  the atom is the entry-in-publication with typed edges (Inspired by/Variations,
  Related to, Also published here) — which map exactly onto Catalog's work-to-work
  adaptation relationships and the Embodiment M:N. Their tree is prop/genre-first
  (Cards = 46% of nodes) with an implicit second axis: the same effect verbs (Vanish,
  Production, Transformation, Transposition, Penetration, Color Change…) repeated
  inside every prop branch.
- **Retailers** (Penguin, Vanishing Inc): five orthogonal axes — genre/performance
  style, product type, venue, difficulty, creator — but difficulty and venue exist only
  as informal tags. Creator pages at `/magician/<slug>` on both sites. No structured
  gating anywhere in the industry (purchase-gating + DRM only).
- **Old-book platforms** (PG/HathiTrust/IA): expected baseline = fielded search +
  year-range + facets (subject/author/language/date); confirmed universal weaknesses a
  focused site beats: no edition grouping (Catalog provides it), subject-vocabulary
  chaos (curated taxonomy provides it), no copyright-status reasoning shown
  (plan 003's Determination provides it).

**Design conclusion:** one hierarchical **Category** tree for the prop/genre axis
(CA's proven shape) + **normalized flat facets** for effect type, venue, and difficulty
(the axes everyone else leaves as tags — making them real facets is the
differentiator). Search/browse UI itself is later controller/view work; this plan is
the model layer that feeds it.

### Decisions

- `Magic::Trick` decorates a trick-shaped `Catalog::Work` (1:1) with domain facets.
  Not every catalog work is a trick (books, treatises); tricks are usually component
  works (a routine within a book, linked via work-relationship `part`).
- `Magic::Listing` decorates a *book-level* `Catalog::Work` (1:1) with public-UI
  concerns: classification, feature/hype flags, blurb, purchase links.
- **Classification speaks the community's language**: enum
  `%w[ beginner_friendly advanced ]` — the owner's own words ("beginner-friendly magic
  books, not advanced secrets"). `beginner_friendly` = anyone may download (early
  Tarbell); `advanced` = requires plan 002's `can_download_advanced?`
  (Magician/Librarian roles). Binary now, extensible. Gating is PDM's own
  community-ethics feature — the industry has no precedent (research confirmed), so
  there is no external convention to match. The classification also drives plan 004's
  print_budget step (budget softcovers for beginner-friendly titles only).
- Whether a file exists to download is **Workflow's** fact (`Project#downloadable?`);
  whether this user may have it is **Magic's** (`Listing#accessible_to?`); the button
  is the conjunction, composed at the controller layer later.
- `Magic::Category` may optionally reference a `Catalog::Concept` (the bridge between
  the domain taxonomy and Group 3 bibliographic subjects — "Cups and balls" is both).

## Entities

Namespace module `Magic`, `table_name_prefix "magic_"`. FKs always
`foreign_key: { to_table: ... }`.

### Vocabularies / taxonomy

- **`Magic::Category`** — hierarchical tree: `name`, `parent` (self-FK, nullable),
  optional `concept` (FK → catalog_concepts). Unique `[parent_id, name]`. Instance
  methods: `path` (breadcrumb array walking parents), `self_and_descendants`
  (recursive CTE scope — SQLite supports `WITH RECURSIVE`). Seed top levels from CA's
  shape (Cards, Coin, Mental Magic, Rope, Silk & Handkerchief, Illusions, …) as
  fixtures/seeds, grown by Librarians.
- **`Magic::Effect`** — flat lookup: `name` unique. "Effect" is the ubiquitous term
  (magicians ask "what's the effect?"), and the canonical vocabulary is **Fitzkee's
  basic effects from *The Trick Brain*** — the very book in the Copyright fixtures.
  Seed from his list (production, vanish, transposition, transformation, penetration,
  restoration, animation, anti-gravity, attraction, invulnerability, identification,
  thought reading, prediction, extra-sensory perception, …) plus the CA-observed
  additions (color change, traveling, levitation). Effects-as-specific-plots (Ambitious
  Card) remain `Catalog::Concept`s / categories — this lookup is the effect *class*.
- **`Magic::Venue`** — flat lookup: `name` unique. Seed: close-up, parlor, stage,
  street, walk-around, virtual.

### `Magic::Trick` (domain view of a routine-work)

| column | notes |
|---|---|
| work (FK → catalog_works, unique) | the routine's Work |
| difficulty | enum `%w[ self_working easy intermediate advanced ]`, nullable (unknown) |
| summary | string — CA-style editorial one-liner ("Queens and Jacks change places…") |

Joins (each a plain join model with unique pair index, house-style over HABTM for the
write API): `Magic::TrickCategory`, `Magic::TrickEffect`, `Magic::TrickVenue`.
Trick `has_many` each + `-through`. Derivation edges between tricks are NOT modeled
here — they're Catalog work-to-work relationships (adaptation/imitation) on the
underlying works; `Trick` exposes them via delegation (`related_tricks` reading the
work's relationships and mapping back through tricks).

### `Magic::Listing` (domain view of a book-level work, for the public UI)

| column | notes |
|---|---|
| work (FK → catalog_works, unique) | |
| classification | enum `%w[ beginner_friendly advanced ]`, default `beginner_friendly` |
| featured | boolean, default false — homepage/search boost (*Greater Magic* hype) |
| blurb | text — public description |

- `accessible_to?(user)` = `beginner_friendly? || user&.can_download_advanced?` — the
  entire gating rule, one predicate, tested exhaustively.
- Copyright status/countdown for display comes from `Copyright::Determination` via the
  work (read across the seam, no duplication).

### `Magic::PurchaseLink` (affiliate/commerce)

listing FK; `label` (retailer name); `url` (presence, no format validation);
`position`. For non-PD works (countdown pages) and in-print PD editions alike.

## Generators

```sh
bin/rails g model magic/category name:string parent:references concept:references
bin/rails g model magic/effect name:string
bin/rails g model magic/venue name:string
bin/rails g model magic/trick work:references difficulty:string summary:string
bin/rails g model magic/trick_category trick:references category:references
bin/rails g model magic/trick_effect trick:references effect:references
bin/rails g model magic/trick_venue trick:references venue:references
bin/rails g model magic/listing work:references classification:string featured:boolean blurb:text
bin/rails g model magic/purchase_link listing:references label:string url:string position:integer
```

Hand-edits: `parent` → `to_table: :magic_categories`, nullable; `concept` →
`to_table: :catalog_concepts`, nullable; `work` → `to_table: :catalog_works` with
unique indexes on trick.work_id and listing.work_id; unique pair indexes on the three
join tables; `classification` null: false default "beginner_friendly"; unique names on
effects/venues and `[parent_id, name]` on categories.

## Tests

- **Gating matrix** (the most important test in the context):
  `listings(:royal_road).accessible_to?(nil)` true (beginner_friendly, signed-out);
  `listings(:greater_magic).accessible_to?(users(:visitor))` false (advanced);
  `...accessible_to?(users(:vetted_magician))` true;
  `...accessible_to?(users(:kerrick))` true (librarian).
- Category: `path` returns breadcrumb ["Cards", "Sleights"]; `self_and_descendants`
  includes children; `[parent_id, name]` uniqueness; root and child both valid;
  concept bridge resolves to `catalog_concepts(:cups_and_balls)`.
- Trick: one trick per work; difficulty vocabulary (invalid value fails validation);
  facet joins round-trip (`tricks(:ambitious_card).categories` includes cards);
  `related_tricks` delegation returns tricks whose works are relationship-linked
  (fixture: add a second trick + a catalog work_relationship to prove it).
- Listing: one per work; classification vocabulary; default beginner_friendly.
- PurchaseLink: url presence; ordering by position.

## Future (explicitly deferred, informed by research)

- FTS5 search index + `Searchable` concerns (house pattern in
  `rails-37signals-models/references/patterns.md`) over listings/tricks/agents — the
  unified metadata+full-text search with year-range and facets that beats PG/HT/IA.
- Public UI: work-grouped results (Catalog gives edition grouping for free — the
  confirmed weakness of all three big platforms), copyright-status reasoning display +
  countdown (plan 003), "hide articles/reviews"-style toggles, A–Z browses, creator
  pages at `/magician/<slug>` (both retailers agree on the URL pattern).
- CA-style niceties when tricks are indexed at scale: per-entry page numbers,
  "description only, no explanation" flag, external scan deep-links (via
  `Workflow::Resource`).

## Context seams

- **Catalog**: trick.work / listing.work / category.concept — read-only references;
  derivation between tricks lives in Catalog's work relationships.
- **Copyright**: listing pages read `Determination#public_domain?` / `countdown_days`
  for badges, countdowns, and whether to show purchase links vs. downloads.
- **Workflow**: `Project#downloadable?` + external `Resource` links (HathiTrust, PG)
  supply what the listing can offer before a PDM edition exists.
- **Users** (plan 002): `can_download_advanced?` is the only identity fact Magic
  consumes.
