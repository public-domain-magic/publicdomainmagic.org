# Plan 002: Accounts & RBAC (Identity Foundation)

## Context

Every other bounded context needs actors and gates before it can be built:

- **Workflow** wants "actors baked in from the beginning" (Researcher role; Kerrick the
  only actor for now).
- **Copyright** dossiers are attributed to a researcher; volunteers must be vetted by
  Kerrick before receiving the role.
- **Magic** (public UI) gates downloads: default/no-role users get `public`-exposure
  books only; the **Magician** role (vetted via S.A.M./I.B.M. comfort) unlocks
  `protected` books (titles whose methods working magicians still rely on — plan 005's
  exposure axis).
- All catalog data is hand-submitted by users with the **Librarian** role.
- **Administrator** grants roles. At launch Kerrick holds all four roles.

Users, sessions, and role grants are app-wide identity infrastructure, not a bounded
context — models live at the top level (`User`, `Session`, `Role`), per the
`rails-37signals-auth` skill (hand-rolled Rails 8 native pattern; no Devise/Pundit).

### Decisions

- **Multiple simultaneous roles** ⇒ the skill's single `enum :role` doesn't fit. Use its
  data-driven join-model pattern: a `roles` table of grants (user × role name), with
  `granted_by` + `note` so vetting is auditable ("S.A.M. member, verified 2026-07").
- **Capabilities, not role checks, at call sites.** Callers ask `can_catalog?`, never
  `role?(:librarian)`. Role-implication lives in exactly one place (the predicate).
  No implication chains: a person holds multiple explicit grants instead (auditable).
- **Absence of role = the public tier** (beginner downloads only). No "member" role row.
- Protected-access gate: `magician? || librarian?` (a Librarian cataloging protected
  books must access them; Administrator is *not* implicitly included — grant the role).
- The public/protected exposure classification of a book itself belongs to the **Magic**
  context (plan 005), not here. This plan only supplies the capability predicate.
- First-run bootstrap (writebook pattern): when `User.none?`, a FirstRuns flow creates
  the first user and grants `administrator`.

## Step 1 — Generators

```sh

#   Current, Authentication concern, Sessions/Passwords controllers, migrations

bin/rails g migration AddNameToUsers name:string

bin/rails g model role user:references name:string granted_by:references note:string
```

**Generator FK trap (same as plan 001, different spelling):** `granted_by:references`
with `foreign_key: true` derives the target table from the column name →
`REFERENCES "granted_bies"`. Hand-edit to `foreign_key: { to_table: :users }`. The
`user:references` FK is fine here (no table prefix at top level).

## Step 2 — Migration hand-edits

`create_roles`:

```ruby
create_table :roles do |t|
  t.references :user, null: false, foreign_key: true
  t.string :name, null: false
  t.references :granted_by, foreign_key: { to_table: :users }   # nullable: first-run/seed grants
  t.string :note

  t.timestamps

  t.index %i[ user_id name ], unique: true
end
```

Review the generated auth migrations; keep as generated (sessions carry `ip_address`,
`user_agent` — the skill's auditable-session pattern).

## Step 3 — Models

```ruby
# app/models/role.rb
# A granted capability tier. Grants are explicit and auditable — who granted,
# when, and on what basis (note). A user may hold several simultaneously.
class Role < ApplicationRecord
  NAMES = %w[ administrator librarian researcher magician ].freeze

  belongs_to :user
  belongs_to :granted_by, class_name: "User", optional: true

  enum :name, NAMES.index_by(&:itself), validate: true

  validates :name, uniqueness: { scope: :user_id }
end
```

```ruby
# app/models/user.rb
class User < ApplicationRecord
  include Rolable

  has_secure_password validations: false   # per auth skill: invited/transferred users may lack one
  has_many :sessions, dependent: :destroy

  normalizes :email_address, with: ->(e) { e.strip.downcase }

  validates :email_address, presence: true, uniqueness: true
end
```

```ruby
# app/models/user/rolable.rb  (capability concern, house style)
module User::Rolable
  extend ActiveSupport::Concern

  included do
    has_many :roles, dependent: :destroy
    has_many :granted_roles, class_name: "Role", foreign_key: :granted_by_id,
             inverse_of: :granted_by, dependent: :nullify
  end

  def role?(name) = roles.exists?(name: name)

  # Capabilities — call sites ask these, never role?(...) directly.
  def can_administer?       = role?(:administrator)
  def can_catalog?          = role?(:librarian)
  def can_research?         = role?(:researcher)
  def can_access_protected? = role?(:magician) || role?(:librarian)

  def grant(name, by:, note: nil) = roles.create!(name:, granted_by: by, note:)
end
```

Adapt the generated `Session` to the skill's pattern (has_secure_token if not generated
that way; `resume` with hourly `last_active_at` throttle is optional now — add the
column only if adopting it). `Current` stays as generated (`session=` cascades to
`user`).

Note: `roles.exists?` per predicate is fine at this scale; if a request checks several
capabilities, memoize (`def role_names = @role_names ||= roles.pluck(:name)`) later —
don't pre-optimize.

## Step 6 — First-run bootstrap (small, from auth-skill variations)

## Context seams

- **Workflow/Copyright** reference `User` for actors/attribution (`belongs_to
  :researcher, class_name: "User"`), and guard with `can_research?`.
- **Catalog** write access guards with `can_catalog?` (controller layer, later).
- **Magic** downloads guard with `can_access_protected?` against its own
  public/protected exposure classification (plan 005).
- Volunteers self-register (standard signup) but hold no roles until granted —
  fail-closed by construction.
